# 规则集与来源

> 首页只讲「能实现怎样的分流」。这一页是组件清单：用了哪些规则集、各自从哪来、按什么顺序生效。

## 1 · 全部规则集

Egern 的规则集**内联在 `rules` 段里**（`rule_set` 条目直接写 `match:` URL），没有独立的 `rule_sets` 段。两个 profile 共用同一批；分流版多 15 条，其中 `Proxy.list` 处于 `disabled` 状态不生效。

## 3 · 排序约束

四条，改动顺序前必须逐条确认。

1. **白名单 `Jinx-CN` 必须排在最前**，且在两条广告规则之前 —— 两份黑名单存在重叠域名，白名单排到后面会被误杀。
2. **厂商专属规则（`OpenAI` / `Gemini` / `Anthropic` / `Claude`）排在 `AI.list` 之前** —— 否则 AI 域名先被 `AI.list` 接走，专属组形同虚设。
3. **Apple 与微信排在 `direct.txt` 之前**（仅分流版有这两条）—— 它们要抢在国内域名规则之前定去向。
4. **`geoip: CN` 排最后，且必须带 `no_resolve`** —— 否则每个走到它的域名都会被强制本地解析一次。详见 [`05-分流与no_resolve必须成对交付.md`](05-分流与no_resolve必须成对交付.md)。

> 🛡️ `.cn` 后缀规则看似冗余（`direct.txt` 已含 `.cn`），保留的理由是**不依赖规则集加载成功**：规则集下载失败时，`.cn` 仍能直连。
