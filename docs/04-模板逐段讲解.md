## 1. 顶层字段

```yaml
ipv6: false                          # AAAA 可绕过 IPv4 侧封堵，关掉
vif_only: true                       # 虚拟网接口模式（非默认值，见下）
hijack_dns:
- '*'                                # 接管 :53 并返回 Fake IP
geoip_db_url: https://.../Country.mmdb
asn_db_url:   https://.../GeoLite2-ASN.mmdb
proxy_latency_test_url:  http://cp.cloudflare.com/generate_204
direct_latency_test_url: http://connectivitycheck.platform.hicloud.com/generate_204
compat_route: false
include_all_networks: false
include_apns: false                  # APNs 走隧道外链路（与 real_ip_domains 配套）
real_ip_domains:                     # 这几个域名不做 Fake IP 映射
- '*.lan'                            # Windows/Apple 的推送与内网发现走隧道外链路，
- '*.local'                          # 用 Fake IP 反而会让推送异常
- '*.push.apple.com'
```

**注意 `proxy_latency_test_url` 与 `direct_latency_test_url` 这两个域名** —— 它们是清单第 15 项的主体：**每轮节点测速都要被解析一次**，所以必须被解析到国内加密 DNS。v10 起不再需要显式规则，由 `forward` 兜底兜住（都指向 `Domestic-DNS`）。模板已覆盖。

> 📌 **`v2.1` 的 §1 比上面这段少 4 行**：`ipv6: false` / `compat_route: false` /
> `include_all_networks: false` / `include_apns: false` —— 它们的值**恰好等于官方默认值**，
> 写与不写是同一份配置，所以在 `v2.1` 里已删除（`v2` 仍保留，可对照）。
> 下面讲的是这些字段**各自管什么**；`vif_only: true` 与 `hijack_dns` 这类**非默认值**则必须显式写。

> `vif_only: true` 是**非默认值**（官方仅说明"虚拟网接口模式，默认 `false`"）。本模板保留原配置取值，**未做验证**。如果你的环境有"某些 App 不走代理"的现象，它是第一个可以拿来 A/B 的开关。

## 2. `dns` 段 ★ 核心

### 2.1 `bootstrap` —— 唯一无法加密的出口

```yaml
  bootstrap:
  - 223.5.5.5
  - 223.6.6.6
  - 119.29.29.29
```

官方原文：`bootstrap` **仅支持传统 UDP:53，且不遵循代理规则（直连）**；用途 ① 解析 `upstreams` 中加密 DNS 服务器的主机名、② 作为最终 DNS 回退；**未配置或解析失败时自动使用系统 DNS**。

**这一段的写法只有一个原则：`bootstrap` 唯一安全的形态是"永远不被触发"。**
列几个国内大厂明文 IP 只是为了把"全失败 → 掉到 `system`（= 运营商）"的概率压到最低
（`v1` 列 3 个，`v2.1` 列 2 个：`223.5.5.5` + `119.29.29.29`）。

> ⚠️ **绝不写 `system`** —— 那等于主动把运营商解析器接进回退链。
> ⚠️ **也不要把希望寄托在"换个更好的 bootstrap IP"上** —— 实测把 `223.5.5.5`/`119.29.29.29` 换成 `180.76.76.76`，泄露的 ISP **仍然是 China Telecom**（明文 `:53` 在运营商线路上会被接管，或失败后掉到系统 DNS）。原因见 [docs/02 末节](02-DNS为什么会泄露.md)。

### 2.2 `upstreams` —— 为什么全部写 IP 字面量

```yaml
  upstreams:
    Domestic-DNS:
    - https://223.5.5.5/dns-query
    - https://223.6.6.6/dns-query
    - https://1.12.12.12/dns-query
    - https://120.53.53.53/dns-query
    - tls://223.5.5.5
    - tls://1.12.12.12

# ⚠️ 模板里 Foreign-DNS 整组已被注释掉（不是未启用，是注释）。原因见下。
#    需要用时取消注释即可，端点如下：
#    Foreign-DNS:
#    - https://8.8.8.8/dns-query
#    - https://8.8.4.4/dns-query
#    - https://1.1.1.1/dns-query
#    - https://1.0.0.1/dns-query
#    - tls://8.8.8.8
#    - tls://9.9.9.9
```

三个设计点：

1. **全是 IP 字面量** ⇒ 消灭 `bootstrap` 用途①（端点上写主机名，官方就会用明文 `bootstrap` 解析它一次）。
2. **两家机构 × 两种协议 × 各两个 IP** ⇒ 官方"同一组内多个服务器并发竞速、最快者胜"，**触发回退的唯一条件是"这一组全部失败"**，端点越多越不可能。
   （`v2.1` 收敛为「各 1 个 IP、共 4 端点」，仍保持「两家机构 × 两种协议」的冗余结构。）
3. **`Foreign-DNS` 必须经代理才可达**：它要求链路是「设备 → 代理 → `8.8.8.8`」，从国内蜂窝上才能建起来。所以它**不能**用作 `forward` 的兜底。

**逐个实测的结论（务必记住这两条）：**

| 端点 | 结果 |
|---|---|
| `https://8.8.8.8` / `8.8.4.4` / `1.1.1.1` / `1.0.0.1` | HTTP 200 ✅ |
| `https://9.9.9.9/dns-query` | ❌ **失败**：`HTTP Version Not Supported` —— Quad9 在该 IP 上只提供 HTTP/3，**不响应 HTTP/1.1 线格式** |
| `tls://9.9.9.9` | ✅ 证书 `CN=dns.quad9.net`，正常应答 ⇒ **Quad9 只能走 DoT** |

> ⚠️ **模板把 `Foreign-DNS` 整组注释掉了，保留定义未删。**
> 原因：v10 起 `forward` 已塌缩为纯国内兜底，本组**没有任何引用**，留着启用只是噪音；
> 但它在"需要境外解析答案"的 A/B 场景里仍有价值，所以按用户要求**保留定义、注释掉**，而不是删除。
> 需要恢复时：取消注释，并把 §2.3 的两条 `forward` 兜底 `value` 改回 `Foreign-DNS`（注意那会引入"先有代理才能解析"的启动期明文风险，见 §2.3）。

### 2.3 `forward` —— 这份配置的分流表

`forward` 决定"哪些域名走哪个上游组"。**v10 起，它塌缩为 2 条兜底规则**，不再枚举任何具体域名：

```yaml
    # 两条兜底：任何域名 -> 国内加密组（v10 起塌缩，与订阅/节点域名解耦）
    - domain_regex:    {match: '.', value: Domestic-DNS}
    - domain_wildcard: {match: '*', value: Domestic-DNS}
```

**为什么能塌缩到 2 条兜底** —— 两个结构性事实（官方 `dns` 文档逐字支持）：① `forward` 的 value 是**单值**（`Domestic-DNS`），官方"规则按声明顺序求值、第一条命中的决定上游"，既然每条结果都一样，规则顺序与域名清单都不影响结果，删掉任何一条、新增任何域名行为都不变（可用 `scripts/audit_dns_forward.py` 验证）；② 配置了 `proxy_nameservers` 后，**代理 DNS 会跳过 `forward`**，节点域名的解析走代理 DNS，根本不查本节。⇒ **换订阅、换机场、换节点域名、换中转 CDN，本段一个字都不用改** —— 这也正是 Surge 那套配置的形态。

**为什么写两条兜底**：`domain_regex` 官方列为 PCRE2 **find** 式（`'.'` 命中任意子串）；`domain_wildcard` 是官方示例与社区配置的主用法。**两条刻意语义不同、互不依赖** —— 任何一条生效，`bootstrap` 都不会成为用户域名的回退。

> ⚠️ **`v2.1` 只保留了其中一条（`domain_wildcard`）。** 依据就是上面 ①：两条 `value` 单值且相同，
> 删掉任何一条行为都不变（`audit_dns_forward.py` 可验证）。保留 `domain_wildcard` 是因为它是
> **官方示例与社区配置的主用法**。想更保守，从 `v1.yaml` 抄回 `domain_regex` 那条即可。

**为什么兜底必须是 `Domestic-DNS`（而不是境外组）**（这一条争议最大）：兜底组的唯一判据是**「直连可达」**，不是「指向国内还是境外」。理由见 [docs/02 附节](02-DNS为什么会泄露.md)：官方只写了"未命中回退 Bootstrap"，"命中组的端点全失败"会怎样**并未写明** —— 兜底挂境外组，就等于把一条未定义分支留给明文 UDP:53；且兜底组若需经代理，启动阶段（规则集与 DB 下载、首轮测速）代理未就绪时，本地解析会掉进 `bootstrap` 明文。实际本地解析只服务于 DIRECT 域名（见 §5 段 C），全是国内与 Apple 域名，国内加密 DNS 更优更快；走代理的域名由节点远程解析，**根本不经过 `dns` 段**。

### 2.4 `proxy_nameservers` —— 一个"不写也有风险"的字段

```yaml
  proxy_nameservers:
  - https://223.5.5.5/dns-query
  - https://223.6.6.6/dns-query
  - https://1.12.12.12/dns-query
  - https://120.53.53.53/dns-query
  - tls://223.5.5.5
  - tls://1.12.12.12
```

官方 `dns` 文档原文：**未配置时，代理 DNS 与默认 DNS 共用 `Forward` 规则，未命中回退到 `Bootstrap`** ——
也就是说，**"不设置"这件事本身，就留下了一条通往明文 UDP:53 的兜底分支**。

设置后的语义是「所有代理 DNS 查询强制走该列表，**`Forward` 规则会被跳过**」，那条回退分支在结构上不再存在。

**为什么只能用国内端点**：代理 DNS 是**强制直连**的（官方：避免 DNS→代理→DNS 循环依赖），境外解析器在国内线路上根本不可达 —— 那正是 `bootstrap` 会被逼出来的原因。

> ⚠️ **这是一个硬覆盖**：一设就绕过 `forward`。如果你发现「节点连不上」，**第一件事就是注释掉这个列表**（`v1` 是 6 行，`v2.1` 是 4 行；等价于回到"不设置"的行为）。

### 2.5 `hosts` 与 `block_ips`

```yaml
  hosts:                        # 把 DoH 域名钉到 IP（仅当 IP 固定时可用）
    dns.alidns.com:
    - 223.5.5.5
    - 223.6.6.6
    doh.pub:
    - 1.12.12.12
    - 120.53.53.53
  block_ips:                    # 丢弃空路由式污染应答
  - 0.0.0.0
  - 127.0.0.1
```

- `hosts` 是"端点写主机名"的**补救措施**（省掉一次解析）。但既然 `upstreams` 已经全用 IP 字面量，这里更多是给**其它**可能解析这些域名的地方兜底。
- `block_ips` 刻意**不放 `10.0.0.0/8`** 等私网段，避免误伤内网域名的解析结果。

> ⚠️ **`v2.1` 把整个 `hosts:` 段删掉了。** 理由是逐项核对后确认：`dns.alidns.com` / `doh.pub` / `dot.pub`
> 这三个映射在本配置里**没有任何引用点** —— `upstreams` 与 `proxy_nameservers` 的端点全是 IP 字面量，
> 没有任何地方会去解析这三个主机名。它属于"端点写主机名"时代的遗留物：留着不报错，删掉也不改变任何行为。
> 若你出于其它考虑仍想保留（例如以后打算把端点改回主机名），从 `v1.yaml` 抄回这 10 行即可。

> **什么时候不要用 `hosts` 钉**：端点 IP 不固定（CDN / Anycast 会变）时，钉死的 IP 一旦失效，整组就废 —— 而"整组失败"正是触发回退的条件。

## 3. `proxies` 段 —— 节点形态决定解析面

> ⚠️ **模板的 `proxies` 是空的（`proxies: []`）** —— 不附带任何示例节点，避免误导。
> 但下面的规律**在你自己填节点时依然成立**，这是本配置最关心的一件事：

| 形态 | 解析面 |
|---|---|
| `server` 写 **IP 字面量** | **零解析** —— 从根上消除"节点域名解析"这条面 |
| `server` 写 **域名** | 必然产生一次**本机 + 直连 + 明文**的解析（代理还没通，只能本地解析它自己的地址） |

⇒ **能写 IP 就写 IP。** 这是唯一从根上消除节点域名解析的办法。

**写域名的节点怎么办？** 这正是 v10 把 `forward` 塌缩成 2 条兜底换来的好处：
**不需要为节点域名做任何事** —— 因为
① 配置了 `proxy_nameservers` 后，代理 DNS **跳过 `forward`**，节点域名根本不查本节；
② 即使查到，两条兜底 `value` 单值（`Domestic-DNS`），任何域名都得到同一个结果。
⇒ 换订阅、换机场、换节点域名，`dns` 段**一个字都不用改**。

**中转节点同样适用**：若你用 `prev_hop` 之类的中转链，中转节点自身的域名也走上面的同一条路径，
无需在 `forward` 里额外列举（这正是 Surge 那版配置里最容易腐化的地方）。

## 4. `policy_groups` 段

**推荐版 `v2.1` 有 29 个策略组**，结构上分四类：

| 类别 | 例子 | 说明 |
|---|---|---|
| 入口 | `Proxy`（`select`）、`Final`（`select`） | `Final` 是兜底组，模板里它只有一个成员 `Proxy` |
| 智能/回退 | `Smart`（`smart`）、`ChatGPT`/`Gemini`（`fallback`） | `smart` = 多轮测速按健康度打分选优；`fallback` = 按 `policies` 顺序试，第一个可用就用 |
| 订阅组 | `Airport-A` / `Airport-B` / `Airport-C` / `Airport-Free`（`external` / `smart` + `urls`） | **模板里 URL 已替换为占位** |
| 地区组 | `Hong Kong` / `USA` / `Japan` / `Taiwan` / `Singapore` / `Korea` / `Other Regions` | 靠 `filter` 正则从订阅里筛节点，`flatten: true` |

> 🧩 **`v0`（极简裁剪版）只有 4 个组** —— `Proxy` / `AI` / `AD` / `Final`，规则也只有 9 条。
> 它另有**两处只属于 `v0`** 的调整，**不同步到其他版本**：
> ① `Final` 组加了 `hidden: true`（它只有一个子策略 `Proxy`，没有手动切换的意义）；
> ② `AD` 组的子策略**只有 `REJECT`**，去掉了 `DIRECT` 兜底。
> 想在 `v0` 里临时放行某个广告域名：在 `rules` 里加一条**更靠前**的 `domain` / `domain_suffix` 规则指向 `DIRECT`
> —— **别整组切走，那等于关掉全部广告拦截**。

> ⚠️ `smart` 组的 `policies:` 里如果出现**节点名**，这些名字必须与 `proxies` 段里的 `name:` 完全一致（模板已对齐）。你替换节点后，**记得同步改这里**。

> ⚠️ **`ChatGPT` / `Gemini` 两组的 `policies` 是空的 `[]`，而规则 3/4 直接指向它们**
> （`OpenAI.list → ChatGPT`、`Gemini.list → Gemini`）。**空组 = 这组没有任何可用出口**，
> 所以在你自己填上之前，**OpenAI / Gemini 分区的流量是断的**。另外 `Google` 组的**第一个成员就是 `Gemini`**，
> 默认选中它 —— 同样直到你填好才通。
>
> 填法二选一：把节点名（或订阅组名，如 `Airport-A`）写进这两组的 `policies`；或直接写成 `- Proxy`
> 让它跟随主入口。**别留着 `[]` 就导入使用。** 同理，`Airport-A/B/C/Free`、`MAX` 的 `urls` 也全是占位订阅地址，
> 不替换就等于这几组里没有节点。
>
> ⚠️ 这两组是 **`fallback`（故障转移）而非 `smart`**，语义差别有实际后果：`fallback` 按 `policies`
> 顺序取**第一个可用**的节点，**不做延迟择优**。所以你把 3 个节点写进去，实际生效的永远是**第 1 个**
> （只有它挂了才轮到第 2 个）。想让它在几个节点里自动挑最快的，得改成 `smart`；想固定走某个地区，
> 现在的写法正合适 —— 把那个节点写在第一位即可。

## 5. `rules` 段 —— 顺序就是一切

**推荐版 `v2.1` 有 24 条**规则（21 条 `rule_set` + 1 条 `domain_suffix: cn` + 1 条 `geoip: CN` + 1 条 `default`）；
`v0` 只留 **9 条**（去广告 3 条 + `Lan` + `AI` + `direct.txt` + `cn` + `geoip:CN` + `default`）。**顺序决定结果**，所以分四段理解：

### 段 A：DNS 端点固定路由 —— **已从模板移除**

模板**不再包含**任何 DNS 端点固定路由规则（原先的 `alidns.com` / `doh.pub` / `dns.google` / `cloudflare-dns.com` 等域名规则，以及 `223.5.5.5` / `8.8.8.8` / `1.1.1.1` / `208.67.x.x` 等一批 `ip_cidr` 规则，共 15 条）。

**为什么可以删**：本模板的 DNS 解析器**全部以 IP 字面量**给出 —— `dns.upstreams.Domestic-DNS`、`dns.proxy_nameservers`、`dns.bootstrap` 里没有任何一个以主机名写的 DNS 端点。解析器直接拿 IP 去查询，**根本不需要**在 `rules` 里把 DNS 端点域名/IP 再钉一遍。这些规则只影响「DNS 查询包的传输路径」（直连还是走代理），**不影响防泄露机制本身**；写错反而可能把国内 DoH 绕到境外。删掉更干净，防泄露能力不变。

> 如果你**自己**的 `dns:` 段用了主机名写的 DoH/DoT 端点（如 `https://dns.google/dns-query`），那才需要在 `rules` 里给它一条 `DIRECT` 路由，否则它会落到 `default → Final → Proxy`。模板默认不需要。

> ⭐ **审计脚本的同步（v3.1，2026-09-20）**：删掉段 A 之后，`check_egern_dns.py` 的
> `group_reach` 判据一度失效 —— 它要求「端点全为 IP **且至少一个在 `rules` 里判给 DIRECT**」，
> 后半句在无段 A 的模板里永远不成立，于是兜底组被恒定判为「依赖代理」，脚本报 3 条 `HIGH`、
> 退出码 1。**这不是配置的问题，是判据的载体选错了。**
> 现已补上**第二判据**：端点全为 IP 且**至少一个是国内知名解析器 IP**（`223.5.5.5` / `119.29.29.29`
> / `1.12.12.12` / `120.53.53.53` 等，内置白名单）时，同样判定为「直连可达」。
> 它保留了 v5 那次踩坑的防护 —— **一个全由境外 IP 组成的组仍然会被判 `HIGH`**（境外解析器必须经代理才可达）。
> 两个脚本（`check_egern_dns.py` 与 `audit_dns_forward.py`）已同步修改，且用反例做了回归验证。

### 段 B：原有规则，顺序保持不变

> 2026-09-21 在段 B **之前**新增两条（位于全部规则最前）：`jinx-ads-rules/surge-white-guard.list` → `DIRECT`（白名单守卫，必须抢在广告规则之前放行）、`jinx-ads-rules/surge-ads.list` → `AD`。原有规则之间的相对顺序不变。

- 去广告 `AWAvenue-Ads-Rule`（启用）
- `Lan.list` → `DIRECT`
- 各分区规则集：ChatGPT / Gemini / Anthropic / Claude / Spotify / YouTube / GitHub / Google / Microsoft / Telegram / Twitter / **Proxy（默认 `disabled: true`，由 `Final` 兜底，需要时可启用）**

> 早期模板曾保留 **10 条 `disabled: true` 的遗留规则**（去广告抓取、NoteGPT、若干重复 IP 直连/代理、Apple push 等），它们默认不生效、只是噪音。模板现已将这 10 条**整条删除**，不再保留。

AI 规则集现已指向 ACL4SSR 的 `AI.list` 远程规则集（commit 固定，避免上游漂移）：`rule_set: {name: AI, match: https://raw.githubusercontent.com/ACL4SSR/ACL4SSR/75f0101039d71724b6e998b34604c2e053580e0c/Clash/Ruleset/AI.list, policy: AI}`。它对应同名 `AI` 策略组；不使用该分组可自行删除此规则或改 `policy`。

### 段 C：直连兜底 —— **本轮修复的核心**

```yaml
# Apple —— 用 No_Resolve 版本（原版有 13 条裸 IP 条目，会强制解析）
- rule_set:
    match: https://raw.githubusercontent.com/blackmatrix7/ios_rule_script/master/rule/Surge/Apple/Apple_All_No_Resolve.list
    policy: DIRECT

# ★ 国内域名直连的**主力**（Loyalsoldier direct.txt：111,160 条纯域名，零 IP 条目）
- rule_set:
    match: https://raw.githubusercontent.com/Loyalsoldier/surge-rules/release/ruleset/direct.txt
    policy: DIRECT

# .cn 整个 TLD 再钉一次（不依赖规则集是否加载成功）
- domain_suffix: {match: cn, policy: DIRECT}

# geoip CN —— 注意 no_resolve 之后**它只对"已经是 IP"的连接生效**
- geoip: {match: CN, policy: DIRECT, no_resolve: true}
```

**国内域名规则集为什么必须是「域名条目足够多」的一份**：
`geoip: CN` 加了 `no_resolve` 后不再匹配域名，国内域名的直连**完全依赖一条纯域名规则集**。
早期模板用 `ChinaMax_All_No_Resolve.list`（111,332 域名 + 12,472 条带 no-resolve 的 IP）；现用
Loyalsoldier **`direct.txt`**（111,160 条**纯域名**：110,607 条 `DOMAIN-SUFFIX` + 553 条 `DOMAIN`，**零 IP 条目**）。
注意别被名字骗了：`ChinaMax.list` 才是那个「听起来最像中国域名表、实际 12,614 条里 12,472 条是 IP、
域名仅 64 条」的 IP 规则集，单用它兜不住域名。（对比见 [docs/05](05-分流与no_resolve必须成对交付.md)。）

**为什么 `direct.txt` 不需要 `no-resolve`**：它是纯域名规则集，只做域名串匹配、**任何情况下都不触发解析**，
`no-resolve` 在这儿是空操作。原先由 ChinaMax 的 IP 条目承担的「已是 IP 的连接」，
由下面那条 `geoip: CN`（带 `no_resolve`）兜住 —— 两条合起来才等价于「国内全覆盖」。

**cn 与 geoip:CN 规则与「国内域名规则集」是绑定的**：`geoip` 加了 `no_resolve` 就不再匹配域名，国内域名的直连**完全依赖那条域名规则**。**动一条必须看另一条。**

### 段 D：兜底

```yaml
- default: {name: Final, policy: Final}
```

`Final` 组（`select`）唯一成员是 `Proxy`。
⇒ **未命中任何规则的域名走代理，由节点远程解析、不经过 `dns` 段。**
日志里看到的 `default → Final → Proxy` 就是这条 —— **它是正常的分流决策，不是泄露**。

> 🧩 `v0` 里 `Final` 被设为 `hidden: true`（成员同样是 `Proxy`，**语义完全不变**，只是不在列表里显示）。
